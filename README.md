# quicktrim
# 🎬 要件定義：簡易動画カットアプリ（Quick Trim）v0.1

> ステータス：未承認 ｜ 追記AI：くろちゃん ｜ 追記日時：2026-06-17
> 

## 📌 背景・モチベーション

- PCでの動画編集（DaVinci Resolve等）は、スマホの動画編集アプリに比べて「カットするまでの工程」が多い
- ファイル読み込み→タイムライン配置→再生ヘッド操作→分割→削除、という手順がスマホの「タップで即カット」に比べて重い
- 素材が多い遠征Vlog・パッキング動画などで、DaVinciに渡す前の粗編集（不要部分の選別）だけを高速化したい

## 🎯 目的・スコープ

- **ターゲットユーザー**：自分専用（ちーちゃん）。公開・配布は今回のスコープ外
- **位置づけ**：DaVinci Resolveの**前段**に置く粗編集ツール。本格編集（テロップ・BGM・カラグレ等）はDaVinci側で行う
- **役割分担**：
    - このアプリ：不要素材の除去・使う区間の選別・1本に粗く繋ぐ
    - DaVinci：テロップ・BGM・本編集

## 🧩 MVP機能要件

1. 動画ファイルの読み込み（ローカルファイル選択）
2. タイムライン表示・再生
3. カットポイント指定（クリック/タップで分割）
4. 不要区間の削除（リップル削除：消した分を詰める）
5. 残す区間だけを繋いで書き出し（DaVinciが読める形式のまま、再エンコードを最小限に）
6. **無音区間の自動検出**：Web Audio APIで振幅解析→候補をタイムライン上にハイライト表示→ユーザーがワンタップで採用/スキップを選択

## 🚫 今回のスコープ外（将来検討）

- フィラー除去（えー・あのー等の自動検出）：Whisper等の音声認識が必要なため、whisper.cpp連携などと合わせて将来フェーズで検討
- テロップ・BGM・カラーグレーディング：DaVinci側の役割のまま
- 他ユーザーへの公開・配布

## 🎥 対応想定フォーマット

- SONY ZV-E10II：MP4（H.264/H.265）、4K/フルHD
- DJI Pocket 2：MP4（H.264/H.265）、4K
- iPhone：MOV（HEVC）、4K前後
- オールドコンデジ（F200EXR・IXY 900IS・S6000・Kodak C1）：Motion JPEG AVI等の可能性あり、解像度はVGA〜720p程度
- 静止画（JPEG等）は基本的に対象外

⚠️ **要確認事項**：古いコンデジのAVI（Motion JPEG）はブラウザ標準デコーダーで再生できない可能性あり。実ファイルでの動作確認が必要。

## 💾 保存・永続化の方針

- **作業中のプロジェクト状態**（カットポイントリスト等）：クラウド保存を希望。Route Replay AppのSupabase基盤を流用できるか検討
- **書き出し後の動画ファイル本体**：クラウドには置かない。ローカルダウンロード（デバイス内 or 外付けメディアはOSのダウンロード先設定で対応）

## 🛠️ 技術メモ（検討中）

- ブラウザ内動画処理：FFmpeg.wasmが候補（カット・結合・書き出しをブラウザ内で完結させる）
- 無音検出：Web Audio APIで振幅解析（軽量処理、サーバー不要）
- 大きめファイル（数百MB〜1GB超）を扱う前提でメモリ・パフォーマンス設計が必要

## 🛠️ 実装進捗（2026-06-17・くろちゃん）

### プロトタイプ v0.1 → v0.2

- ブラウザ単独HTMLとして実装（Quick Trim）
- タイムラインのドラッグ範囲選択＋削除区間リスト管理
- **分割→クリップ選択→削除**フローを追加（DaVinci的なリップル削除に近い操作感）
    - 再生位置で「ここで分割」→クリップが2つに分かれる→クリックして選択→「選択中のクリップを削除」
    - 初期実装でクリップクリックと再生位置移動が競合するバグがあったが解消済み（クリップ1個のうちは選択無効化、クリック時は必ず再生位置も移動）
- 無音区間の自動検出（Web Audio APIでRMS解析、感度・最短無音長をスライダー調整、候補を個別に採用/スキップ）

### 書き出し機能（FFmpeg.wasm）

- CDN（unpkg）から`@ffmpeg/ffmpeg` `@ffmpeg/core` `@ffmpeg/util`を動的読み込み（COOP/COEP不要のシングルスレッド版）
- **高速書き出し（デフォルト）**：`-c copy`＋入力シーク（`-ss`を`-i`の前）でキーフレーム単位の高速カット、再エンコードなし
- **正確に書き出し**：出力シーク＋`libx264`再エンコード、フレーム精度だが低速
- 複数の残す区間がある場合：セグメントごとに切り出し→`concat`で結合
- 進捗バー表示、完了後にBlobダウンロードリンクを表示

### 未検証事項

- 検証環境（サーバー上のヘッドレスChromium）に動画コーデックが入っておらず、実ファイルでの動作確認は未完了
- 実機（MacBook Air M2 / ThinkPad）の通常ブラウザでの動作確認が次のステップ
- オールドコンデジAVI（Motion JPEG）の読み込み可否も実機確認待ち

### チャピの提案

- ちーちゃんの運用がiPhone＋Reframe（縦横変換）中心になり、ZV-E10M2は手放した
- Reframe後の素材は手ぶれ補正が未適用の場合がある
- 「全体スタビライズ→カット」ではなく「カット→残ったクリップだけスタビライズ」の順序がVlog用途では効率的
- FFmpegの`-vf deshake`（vidstab系）で実装可能、ただし再エンコードが必要
- 提案ロードマップ：v0.1 MVP（カット・リップル削除・高速書き出し）→ v0.2 手ぶれ補正（弱/中/強）→ v0.3 無音自動カット
- 将来的にはクリップ単位で「Stabilize」チェックボックスを付ける案も

### くろちゃんの所見（要件定義の境界線との整合性）

- Quick Trimの当初の役割定義は「DaVinciの前段＝不要素材の除去・粗い繋ぎのみ」「画質を作り込む工程（テロップ・BGM・カラグレ・スタビライズ含む）はDaVinci側」という分担
- 手ぶれ補正をQuick Trimに入れると、MVPの「高速・軽量」という性格と矛盾するリスクがある（FFmpeg.wasmでの`deshake`は重い再エンコード処理）
- DaVinci Resolve標準のStabilization機能の方が品質・速度のバランスが良い可能性がある
- 「カット→補正」の順序自体は、Quick Trimに機能追加しなくても運用フロー（DaVinciでカット済みクリップにスタブ適用）を変えるだけで実現できる

### 結論（ちーちゃん判断・2026-06-17）

- **まだ決めない。** MVP（カット＋高速書き出し）を実際に使い込んでから、手ぶれ補正をQuick Trim側に入れるかDaVinci側に任せるか判断する
- 次の判断ポイント：実際にDaVinciでスタブ適用する手間が気になるレベルかどうかを使用感から見る

## ✅ 書き出し機能 動作確認完了（2026-06-18）

### 発生した問題と解決の経緯

1. **アーティファクトの更新漏れ**：FFmpeg.wasm組み込み後、作業用ファイルは更新されていたが出力先（ダウンロード用ファイル）へのコピーを一度忘れ、ちーちゃんが古いバージョンを開いて「実書き出しできない」という事象になった → 出力先に正しくコピーして解消
2. **`file://`での直接オープン問題**：ローカルHTMLをダブルクリックで開くと`origin: null`になり、FFmpeg.wasmが使うWeb Workerの構築がブロックされる（`SecurityError: Failed to construct 'Worker'`） → `python3 -m http.server`でローカルサーバーを立て、`http://localhost:8765/quicktrim.html`経由で開く運用に変更
3. **`classWorkerURL`とWorkerのtype不整合（本質的な原因）**：FFmpeg.wasm（`@ffmpeg/ffmpeg@0.12.10`）は`classWorkerURL`指定時、内部のWorkerを`{type:"module"}`で起動する。しかしWorker本体のコード（814.ffmpeg.js）は`importScripts()`を使うクラシックスクリプト形式で書かれており、ESモジュールのWorker内では`importScripts()`が呼び出し時に例外になる（`Module scripts don't support importScripts()`）という、ライブラリ自体の既知の不整合だった（GitHub issue #694等で同様の報告あり）
    - 解決策：`ffmpeg.js`本体をCDNから`fetch`し、`new Worker(new URL(s,"file:///..."),{type:"module"})`の`{type:"module"}`指定を正規表現で除去してクラシックWorkerとして起動するように動的にパッチしてから読み込む（`loadPatchedFFmpegScript`関数）

### 検証方法

- サーバー上のヘッドレスChromium環境にはH.264デコーダーがなく、実機と同じ条件でのテストはできなかったため、WebM/VP8形式のテスト動画でFFmpeg.wasmの読み込み・Worker通信・コマンド実行（分割→削除→exec）が一通り動くことをplaywrightで自動テストし、ロジック面の正しさを確認
- 最終確認は実機（MacBook Air M2・Chrome、ローカルサーバー経由）でちーちゃんが実施 → 書き出し・ダウンロードまで成功

### 現在の構成（最新版）

- `@ffmpeg/ffmpeg@0.12.10` + `@ffmpeg/core@0.12.6`（公式リリースノートに対応したバージョン組み合わせ）
- `unpkg`からCDN経由で読み込み、`toBlobURL`でBlob化
- 高速書き出し（`-c copy`・入力シーク）をデフォルト、正確に書き出し（再エンコード・出力シーク）を選択可能
- 複数の残す区間がある場合はセグメント切り出し→`concat`で結合

### 運用上の注意（重要）

**Quick Trimは `file://` で直接開くと書き出し機能が動かない。** 必ずローカルサーバー経由（`python3 -m http.server` など）で `http://localhost:ポート番号/quicktrim.html` として開く必要がある。今後の改善候補として、初回起動時に`file://`を検知して案内文を表示する仕組みを入れても良さそう。
